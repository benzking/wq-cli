图片本地化 — 核心改动

流程对比
❌ 当前方案：代理模式 
抓取文章 → HTML 内容存入 DB
         → 图片 URL 替换为 /api/image?url=...
         → 每次查看文章实时走代理请求微信 CDN
  • 依赖代理网络稳定性
  • 微信 CDN 可能失效
  • 每次浏览都重新请求图片
✅ 新方案：本地化存储 
抓取文章 → HTML 内容存入 DB
         → 同时下载所有图片到本地
           data/images/{article_id}/...
         → HTML 中图片替换为 /static/images/{article_id}/...
  • 一次抓取，永久可用
  • 不依赖微信 CDN
  • 支持离线浏览
  • 导出时图片已在本地

图片本地化后端实现要点

存储结构 
data/
├── rss.db
├── images/           ← 新增
│   └── {article_id}/
│       ├── img_001.jpg
│       ├── img_002.png
│       └── ...
└── exports/          ← 新增(临时)
    └── {article_id}_export.zip
改动范围
  • content_processor.py — 抓取时下载图片+替换路径
  • article_fetcher.py — 批量抓取时处理图片
  • app.py — 挂载 /static/images 静态目录
  • rss_store.py — 新增 star/unstar/re-export 接口
  • 新增 routes/export.py — MD+图片 zip 打包
⚠️ 影响评估
图片本地化是本次重构中最大的后端改动。它穿透了抓取→存储→浏览→导出全链路。建议在实现计划中将此项独立为一个子任务，和前端 UI 重构并行推进。
